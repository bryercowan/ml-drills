    Deep Dives¶

    Commonly confused topics, explained precisely.

    Self-Attention vs Cross-Attention¶

    Self-attention: Q, K, and V all come from the same source. Each token in a sequence attends to every other token in that same sequence. This is how a Transformer encoder processes a sentence — every word looks at every other word.

    Cross-attention: Q comes from one source, K and V come from a different source. This is how a decoder attends to an encoder's output — the decoder's tokens (queries) look up relevant information from the encoder's representations (keys and values).

    Concrete example: In a text-to-image model, the image generation network uses self-attention to model spatial relationships between patches, and cross-attention to pull in information from the text embedding. The text is the K/V source; the image features are the Q source.

    Rule of thumb: Self-attention = reasoning within a modality. Cross-attention = communication between modalities or between encoder and decoder.

    Pre-Norm vs Post-Norm¶

    Post-norm (original Transformer): 

    1
2
    x = x + Attention(LayerNorm(x))  ← NO, actually:
x = LayerNorm(x + Attention(x))

    Pre-norm (modern default): 

    1
    x = x + Attention(LayerNorm(x))

    In post-norm, the residual connection feeds into the layer norm. In pre-norm, the layer norm is applied before the attention/FFN, and the residual connection bypasses the norm entirely.

    Why pre-norm won: Pre-norm gives cleaner gradient flow through the residual path. With post-norm, gradients at initialization can be unstable, often requiring learning rate warmup. Pre-norm is more stable to train, especially for deep networks. The tradeoff: post-norm can achieve marginally better final performance when carefully tuned, but pre-norm is far more robust.

    Why LoRA Works¶

    Fine-tuning changes weights by a matrix ΔW. Research showed that ΔW has low intrinsic rank — even for a 4096×4096 weight matrix, the meaningful update lives in a subspace of dimension ~4-64.

    LoRA directly parameterizes this: ΔW = BA where B ∈ R^{d×r} and A ∈ R^{r×d}. Instead of learning d² parameters, you learn 2dr — a reduction of d/(2r), which is ~100-1000× for typical models.

    Why low rank? Fine-tuning adjusts a pretrained model for a specific task. Since the model already has strong representations, the adjustment is a small, structured perturbation — not a random full-rank change. The pretrained model did the "heavy lifting" of learning the weight structure; fine-tuning only needs to nudge it.

    Practical notes: Rank 8-16 works for most tasks. Apply to attention projections (Q, V) first — they benefit most. Initialize A with random Gaussian, B with zeros, so ΔW starts at zero. Scale by α/r to decouple the learning rate from the rank choice.

    Why Diffusion Works¶

    Diffusion models define a forward process that gradually destroys data by adding noise:

    1
    q(x_t | x_{t-1}) = N(x_t; √(1-β_t) x_{t-1}, β_t I)

    After enough steps, x_T ≈ N(0, I). The model learns the reverse:

    1
    p_θ(x_{t-1} | x_t) = N(x_{t-1}; μ_θ(x_t, t), σ_t² I)

    Why it works mathematically: Training maximizes a variational lower bound (ELBO) on the log-likelihood. This decomposes into a sum of KL divergences at each timestep, each being a simple denoising objective. The simplified loss becomes: L = E[||ε - ε_θ(x_t, t)||²] — just predict the noise that was added.

    Why it works intuitively: The model only needs to make tiny corrections at each step. At high noise levels, it learns global structure (overall shape). At low noise levels, it learns fine details (textures, edges). This coarse-to-fine hierarchy emerges naturally from the noise schedule.

    KL Divergence¶

    KL divergence measures how much one probability distribution differs from another: KL(P || Q) = Σ P(x) log(P(x)/Q(x)).

    The asymmetry matters:

    • KL(P || Q) — "forward KL" — is infinite when Q assigns zero probability where P is nonzero. This is mode covering: Q must spread mass everywhere P has mass. Used in variational inference (ELBO).
    • KL(Q || P) — "reverse KL" — is infinite when P assigns zero probability where Q is nonzero. This is mode seeking: Q can concentrate on a single mode of P and ignore others. Used in policy optimization.

    In ML: Cross-entropy loss = H(P) + KL(P || Q). Since H(P) is constant for fixed data, minimizing cross-entropy = minimizing KL divergence. In RLHF/DPO, a KL penalty keeps the fine-tuned model close to the base model, preventing reward hacking.

    Overfitting vs Underfitting¶

    Underfitting: Model is too simple to capture the pattern. Training loss is high. Validation loss is high. Both are bad.

    Overfitting: Model memorizes training data rather than learning generalizable patterns. Training loss is low. Validation loss is high (or rising). The gap between them is the problem.

    How to diagnose:

    Signal Underfitting Overfitting
    Training loss High Low
    Validation loss High High (or increasing)
    Train-val gap Small Large

    Fixes for underfitting: Larger model, train longer, reduce regularization, lower learning rate, better architecture.

    Fixes for overfitting: More data, data augmentation, dropout, weight decay, early stopping, smaller model, reduce learning rate.

    Key insight: Modern large models are often in the "double descent" regime — they're so overparameterized that they go past overfitting and generalize well again. But for typical-sized models, the bias-variance tradeoff still applies.

    Training vs Inference Memory¶

    Training uses 3-4× more memory than inference because you need to store intermediate values for backprop.

    Inference memory:

    • Model parameters (e.g., 7B × 2 bytes at fp16 = 14 GB)
    • Activations for the current forward pass (relatively small)

    Training memory adds:

    • Gradients: Same size as parameters (1×)
    • Optimizer states: Adam stores first moment (m) and second moment (v) — 2× parameters. So AdamW needs 3× parameter memory just for optimization.
    • Activations cache: Must store intermediate activations from the forward pass for backprop. This scales with batch size and sequence length. Often the dominant cost.

    Quick math for a 7B parameter model at fp16:

    • Parameters: 14 GB
    • Gradients: 14 GB
    • Adam states (fp32): 56 GB (m + v + master weights)
    • Activations: varies, often 10-30+ GB
    • Total: ~100+ GB to train vs ~14 GB to run

    Memory-saving techniques: Gradient checkpointing (recompute activations instead of storing), mixed precision training, gradient accumulation (smaller batches), ZeRO/FSDP (shard across GPUs).

    Batch Norm vs Layer Norm¶

    Both normalize activations to stabilize training, but they normalize over different dimensions.

    Batch Norm: Normalizes across the batch dimension for each feature/channel. For a batch of 32 images with 64 channels, it computes mean and variance across the 32 images separately for each channel. Uses running statistics at inference.

    Layer Norm: Normalizes across the feature dimension for each example. For a single sequence token with 512 features, it computes mean and variance across those 512 features. No dependence on batch size.

    Why Layer Norm won for Transformers:

    • Batch norm breaks with variable-length sequences (what's the "same feature" across different positions?)
    • Batch norm behaves differently at train vs inference (running stats), adding complexity
    • Batch norm doesn't work well with small batch sizes (noisy statistics)
    • Layer norm is independent of batch size and consistent at train/inference time

    When to use Batch Norm: Still useful in ConvNets (spatial features + fixed spatial dimensions). Works well when batch sizes are large and feature dimensions are spatial.

    When to use Layer Norm: Transformers, RNNs, any sequence model, or when batch sizes are small/variable. This is the default for modern architectures.
